# الاختبارات والفحص — عقلني

## 1) اختبارات الوحدة (تُشغّل في CI، دون جهاز)
`app/src/test/java/com/aqlni/game/LevelPolicyTest.kt`:
- تحويل نسبة نتيجة التقييم إلى مستوى (مطابقة حدود 0.9 / 0.75 / 0.6 / 0.4).
- منحنى XP للمستويات.
- عوالم مفتوحة حسب مستوى اللاعب (`unlockedWorlds`).

تُشغّل آليًا في GitHub Actions قبل بناء APK (`testDebugUnitTest`).

## 2) فحص جودة بنوك الأسئلة (محليًا، Node)
```bash
node tools/validate-banks.js
```
يفحص لكل سؤال:
- عرض 4 خيارات، فهرس الإجابة صحيح، الإجابة الأولى من الخيارات (`a: 0`).
- عدم تكرار المعرّفات أو الخيارات.
- لمس صعوبة 1..5 وصحّة نص السؤال والسبب.
- التوزيع على مستويات الصعوبة (يظهر جدولًا لكل بنك).
- لا وجود لرمز تالٍ (U+FFFD) بعد أي جيل نص عربي.

## 3) فحص صياغة كل ملف JS
```bash
node tools/check-assets.js
```
يتأكد أن كل نص ضمن `index.html` موجود وأنه صياغته سليمة.

## 4) فحص يدوي (Checklist) قبل النشر
- [ ] التقييم الأولي يجري ويحدد المستوى.
- [ ] زر الراجع: في نافذة مفتوحة → إغلاقها؛ في اللعبة → استراحة؛ في قسم → قائمة الأب؛ الرئيسية → نافذة الخروج العربية.
- [ ] كل زر في الرئيسية يفتح شاشات فعالة (بلا شواشة فارغة).
- [ ] الصوت الناطق: جرب زر «أعد السؤال» داخل كويز.
- [ ] الاحتفال (confetti) وصندوق الكنز يظهران على النجاح.
- [ ] الإغلاق الكامل ثم الفتح يعيد التقدم كاملًا.
- [ ] الوضع الليلي يطبق على كل الشاشات المفتوحة الجديدة.

## 5) بناء CI
- `testDebugUnitTest → lintDebug → assembleDebug assembleRelease`
- أرتيفكت: `aqlni-debug-apk` و`aqlni-release-apk`.
- إن اشتكى أي بناء، افتح «Actions» وشاهد السجل الصريح لأول خطوة فاشلة.
